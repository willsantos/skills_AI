# Casos de avaliação Angular

1. Implementar feature em Angular 22: standalone, lazy route, projeto organizado por domínio.
2. HTTP autenticado por cookie: headers XSRF Angular com validação real .NET; não alegar proteção sem backend.
3. Backend renomeou campo: SDK OpenAPI regenerado e testes de contrato, sem DTO duplicado.
4. Frontend antigo com NgModules: não realizar migração global sem pedido.
5. `canActivate` protege acesso? Deve explicar que apenas backend faz autorização.
6. Build em VPS: Angular CLI apenas no CI, confirmar `outputPath` real, fallback de SPA.
7. RxJS mal gerenciado: cancelamento/interop e subscriptions limpos, sem efeitos duplicados.
8. Falha de contrato 409/422: UI trata sem esconder detalhes de campo ou propagar stack traces.
